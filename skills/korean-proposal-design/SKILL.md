# Korean Proposal Design (Anti-AI-Slop)

한글 제안서에서 "AI가 만든 티"를 구조적으로 제거하기 위한 단일 통합 스킬. 규칙의 **단일 원본은
`assets/PROPOSAL.DESIGN.md`** 이며, 외부 참고 자료는 `references/resources.md` 에 있다. 이 SKILL.md는
그 둘을 언제·어떻게 적용하는지의 **워크플로우**만 담는다(규칙 중복 서술 없음).

## 언제 사용하나

- 한글 제안서·기획서·IR·공문 등을 Claude Design 또는 HTML 아티팩트로 만들 때
- 결과물이 "AI 느낌"이 난다(문단 간격 제각각, 페이지마다 레이아웃 흔들림, 도형 겹침/모서리 제각각)
- 우수제안서 톤앤매너를 유지하며 일관된 표지·목차·간지·본문·도표 페이지를 뽑고 싶을 때

## 왜 AI 티가 나는가 (핵심 원인)

맥락(DESIGN.md)이 없으면 모델은 기본 미학으로 수렴하고 문단마다 임의 margin을 넣는다.
- **문단 간격 틀어짐** ← 간격 스케일 미강제
- **템플릿 드리프트** ← 페이지 마스터 재사용 규칙 없음
- **도형 오류** ← radius/정렬 규칙과 출고 전 검수 루프 없음
- **한글 어색함** ← 한글 조판(줄바꿈·행간·자간) 미고려

→ 이 스킬은 위 4가지를 `assets/PROPOSAL.DESIGN.md` 의 규칙으로 각각 차단한다.

## 워크플로우

1. **슬롯 채우기** — `assets/PROPOSAL.DESIGN.md` 의 `{{FONT}}` `{{FONT_HEADING}}`
   `{{BRAND_COLORS}}` `{{REFERENCE_PROPOSAL}}` 를 사용자의 폰트·브랜드색·우수제안서로 교체한다.
   (폰트·우수제안서는 사용자가 직접 삽입한다.)
2. **주입** — Claude Design 새 프로젝트 첫 메시지에 채워진 `PROPOSAL.DESIGN.md` **전체**를 붙여넣는다.
   (코드/에이전트 환경이면 이 스킬이 로드된 상태에서 해당 파일 규칙을 그대로 준수해 생성한다.)
3. **생성 순서** — 표지 → 목차 → 간지 → 본문 → 도표 → 마무리. **페이지 타입별 마스터를 먼저 확정**한 뒤
   이후 페이지는 마스터를 복제해 내용만 교체한다.
4. **자가 검수** — 완성 후 `PROPOSAL.DESIGN.md` §7 체크리스트를 스스로 점검해 위반 0건을 확인한다.
5. **정량 감사(선택)** — `references/resources.md` 의 claude-design-auditor-skill(한글 지원)로
   간격·도형·문단·대비를 점수화 점검한다.
6. **수정** — 재생성 대신 **Tweaks(부분 수정)** 로 반복한다. 재생성할수록 규칙이 흐트러진다.

## 파일 구성

- `assets/PROPOSAL.DESIGN.md` — 붙여넣기용 디자인 시스템(규칙 단일 원본 + 사용자 슬롯 + 검수 체크리스트)
- `references/resources.md` — 한글 지원 GitHub 스킬·DESIGN.md·Figma(.fig) 링크, 출처

## 원칙 (요약)

규칙 본문은 재서술하지 않는다. 항상 `assets/PROPOSAL.DESIGN.md` 를 단일 진실 원본으로 참조·적용하라.
핵심 축만 요약하면: **8pt 간격 스케일 강제 / 고정 radius 세트 / 페이지 마스터 재사용 /
한글 조판(keep-all·행간 1.6–1.75·자간 -0.01~-0.02em) / 안티슬롭 금지목록 / 출고 전 자가 검수.**
